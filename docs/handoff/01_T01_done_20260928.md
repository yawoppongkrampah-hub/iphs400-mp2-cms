## Things not obvious from the code
- Sign-in identifier is the **username**, not an email. `tests/conftest.py` `client_as(role)` signs in with a CSRF token against a per-test seeded temp DB. `csrf_token(client, path)` and `token_in(html)` are the helpers for tests that POST.
- `test_t00.py::test_admin_console_answers` was edited on purpose to sign in first, because signed-out `/admin` now redirects to `/login`.
- `create_app(database=Path)` takes a DB path (default `settings.DATABASE_PATH`). Schema is created on first `db.connect()`.
- Guards: `security.AdminGuard` middleware protects every `/admin*` path. CSRF is an app-wide dependency (`security.verify_csrf`), so new POST routes get it automatically. Admin templates should render through `web.render` to get the token; forms need `<input type="hidden" name="csrf_token" value="{{ csrf_token }}">`.
- `web.render` sets `home_path="/admin"` on the shared `base.html`. Never reuse that context in the publish step.
- `.env` is not auto-loaded. Use `uv run --env-file .env ...`.
- Admin pages have no stylesheet yet (`base.html` links a relative `style.css`, which 404s under the admin).
- Session-per-phase rule: write the ticket id (e.g. `T02`) to `.claude/state/phase` at the start of the session. That file is gitignored. Commits must start `T0N:` and end with `Closes #N`, and code-review findings must be posted on the issue before the closing commit.
